6. **Real bug found and fixed during Phase 2 verification** (not cosmetic): the hashtag-toggle JS (`toggleHashtag`) used single-backslash `\t` / `\n` / `\s` inside `ui.py`'s giant **non-raw** Python triple-quoted HTML/JS template string. Python was silently converting `\t` and `\n` into literal raw tab/newline **bytes** before they ever reached the browser (triple-quoted strings still interpret standard escapes unless prefixed `r"""` — which this one isn't). A raw unescaped newline byte inside a JS regex or string literal is a syntax error in JS (unterminated literal). **Fixed by double-escaping** (`\\t`, `\\n`, `\\s`) so Python leaves a literal single backslash for the browser's JS engine to interpret correctly. Verified by curling the actual served page and confirming the JS source now contains real `\t`/`\n`/`\s` escape sequences, not raw control characters. **This is a standing hazard for any future edit to this file**: `ui.py`'s HTML/JS is embedded in one big non-raw `"""..."""` string — any new JS regex or string literal containing `\d`, `\w`, `\b`, etc. needs to be double-backslashed in the Python source, or it will silently corrupt at import time with only a `SyntaxWarning` (or nothing at all, for the escapes that happen to be valid Python escapes like `\n`/`\t`, which is the more dangerous case since there's no warning at all).
